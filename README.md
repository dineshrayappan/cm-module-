# TexCompliant™ - Garment Compliance Management System

A production-ready, full-stack enterprise web application engineered specifically for apparel and textile manufacturing factories to manage end-to-end compliance operations, buyer audit readiness, non-conformities (NC), corrective action plans (CAP), evidence verification, and dynamic weighted compliance scoring.

---

## 1. System Architecture & End-to-End Workflow

The application implements the complete manufacturing compliance lifecycle:

```text
Compliance Standards (BSCI, WRAP, ISO 14001, OHSAS, Buyer CoC)
        ↓
Compliance Requirements (Granular clauses with frequency, risk, & evidence rules)
        ↓
Departments (HR, Production, Quality, EHS, Maintenance, Stores, Security, Compliance)
        ↓
Automated Compliance Tasks (Periodic inspections generated by schedule cron)
        ↓
Task Execution & Evidence Upload (Mandatory photo/doc attachments)
        ↓
Internal Audits & Buyer Assessments
        ↓
Interactive Audit Checklist (Compliant / Non-Compliant / Observation / N/A)
        ↓
Findings & Non-Conformity (NC) Recording
        ↓
5×5 Risk Assessment Matrix (Likelihood × Impact = Critical / High / Medium / Low)
        ↓
Corrective Action Plan (CAP) Formulation (Immediate, Root Cause, Corrective, Preventive)
        ↓
Evidence Upload (Certificates, rework photos, calibration reports)
        ↓
CAP Review & Workflow Approval (Approved / Rejected with rework instructions)
        ↓
Auditor On-Site Verification (Pass / Fail)
        ↓
NC Closure (Strictly locked until verification pass)
        ↓
Configurable Department & Factory Compliance Score
        ↓
Executive Management Dashboard & Buyer Reports (Export to CSV/Print)
```

## 2. Technology Stack

* **Frontend**: React 19 + Vite 8
* **Styling**: Modern Responsive Vanilla CSS Design System with CSS variables, Outfit & Plus Jakarta Sans typography, KPI cards, badges, modal dialogs, and 5×5 interactive risk matrices.
* **Charts**: Recharts (Department compliance bar charts, monthly compliance trends, NC severity donut charts, and aging bracket distributions).
* **Backend**: Node.js + Express REST API with security middleware (CORS, Morgan, JWT, Multer file upload).
* **Database**: Supabase PostgreSQL with UUID keys, foreign key constraints, performance indexes, and **Row Level Security (RLS)** policies. Includes an out-of-the-box dual-mode adapter with pre-seeded data for immediate local evaluation without external dependencies.
* **Authentication & RBAC**: Supabase Auth + JWT tokens supporting 7 role tiers with an instant Role Switcher in the top header.
* **File Storage**: Supabase Storage (`compliance-evidence` bucket) with local `/uploads` fallback.

## 4. User Roles & Role-Based Access Control (RBAC)

The system enforces granular access controls across 7 distinct roles:

| Role | Permissions & Scope |
| :--- | :--- |
| **Super Admin** | Full system governance, factory setup, user assignment, scoring formulas, and escalation settings. |
| **Compliance Head** | Factory-wide visibility, CAP approval/rejection, high-level verification, executive scorecard review. |
| **Compliance Manager** | Requirement definitions, periodic task assignment, audit oversight, NC triage, report generation. |
| **Internal Auditor** | Conducting audits, checklist execution, finding non-conformities, CAP evidence verification. |
| **Department Manager** | Department-specific tasks, responding to NCs, formulating CAPs, uploading evidence, tracking department score. |
| **Department User** | "My Tasks" view, routine inspection checklist completion, evidence photo attachment. |
| **Viewer** | Read-only executive view across dashboards, reports, and audit histories. |

> **Interactive Persona Switcher**: In the header bar, click the user badge to instantly switch between all 7 roles to test different permissions and UI views.

## 5. Important Workflow Rules Implemented

1. **Mandatory Evidence on Completion**: A task cannot be marked `Completed` without attaching verified evidence if the underlying requirement specifies `evidence_required: true`.
2. **Audit Checklist Non-Compliance Trigger**: Marking any checklist item as `Non-Compliant` automatically raises or links to a tracked Non-Conformity ticket.
3. **Responsible Assignee & Target Date**: Every NC requires a designated responsible person and a committed target resolution date.
4. **CAP Submission Before Review**: Corrective Action Plans must transition from `Draft` → `Submitted` before managers can review or approve them.
5. **Rework for Rejected CAPs**: A rejected CAP transitions to `Rejected` and must be edited and resubmitted with corrective remarks.
6. **Mandatory Evidence Prior to Verification**: When evidence is required, CAP status cannot transition to `Verification` without uploaded documentation.
7. **Auditor Verification Gatekeeper**: Only authorized Auditors or Compliance Heads can perform verification (Pass / Fail).
8. **Lock on NC Closure**: An NC **cannot be closed** without an approved CAP and a verified **Pass** record.
9. **Automatic Overdue Identification**: Automated scheduler identifies overdue tasks and NCs, updating statuses and flagging items in red.
10. **Multi-Tier Escalation Hierarchy**:
    - *Due Date Reached*: In-app reminder notification to assignee.
    - *3 Days Overdue (Level 1)*: Escalation notification to Department Manager.
    - *7 Days Overdue (Level 2)*: Escalation notification to Compliance Manager.
    - *14 Days Overdue (Level 3)*: Urgent escalation to Executive Compliance Head.
11. **Configurable Scoring Engine**: Scoring weights are stored in the database (`score_configurations`) and can be adjusted via the UI (Settings page) without redeploying code.
12. **Immutable Audit Trail**: All mutations (NC creation, status changes, CAP reviews, verifications, and closures) are permanently logged in `audit_logs` with timestamps, actor IDs, and JSON state diffs.

## 6. Quick Start Guide

### Prerequisites
* Node.js v18+ (tested on Node.js v24)
* npm v9+

### Step 1: Start the Backend REST API
Open a terminal in the project directory:

```bash
cd backend
npm install
npm start
```
The backend API server boots on **`http://localhost:5000`** with the pre-seeded in-memory/Supabase adapter and periodic cron evaluator.
* Health Check: `http://localhost:5000/health`
* Dashboard Summary: `http://localhost:5000/api/dashboard/summary`

### Step 2: Start the Frontend Application
Open a second terminal:

```bash
cd frontend
npm install
npm run dev
```
The modern React application launches on **`http://localhost:3000`** with an automated proxy forwarding all `/api` requests to the backend server.

## 7. Supabase Cloud Configuration (Optional)

To connect the application to an active Supabase Cloud project:

1. Create a project on [database.new](https://database.new).
2. Go to the **SQL Editor** in your Supabase dashboard and run `supabase/schema.sql` to initialize all 16 tables, foreign keys, indexes, and Row Level Security (RLS) policies.
3. Run `supabase/seed.sql` to populate sample factories, standards, requirements, audits, and non-conformities.
4. Create a public Storage bucket named `compliance-evidence`.
5. Update `backend/.env` with your project credentials:
   ```env
   PORT=5000
   SUPABASE_URL=https://your-project.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=your-supabase-service-role-key
   JWT_SECRET=your-secure-jwt-secret-key
   ```
6. Restart the backend. The universal database adapter will automatically connect to your cloud PostgreSQL instance.

## 8. REST API Reference

### Authentication & Profiles
* `POST /api/auth/login`: Authenticate with email/password.
* `GET  /api/auth/me`: Get current authenticated profile and permissions.
* `POST /api/auth/switch-role`: Instant demo persona switcher.
* `GET  /api/auth/users`: List factory personnel with contact details.

### Compliance Standards & Requirements
* `GET  /api/standards`: List standards with versioning and review dates.
* `POST /api/standards`: Create a new compliance standard.
* `GET  /api/requirements`: Filter requirements by standard, department, or risk level.
* `POST /api/requirements`: Create a new compliance clause with frequency and evidence rules.
* `POST /api/requirements/trigger-auto-tasks`: Manually trigger task generation.

### Tasks Management
* `GET  /api/tasks`: List all tasks with department, status, priority, and date filters.
* `GET  /api/tasks/my-tasks`: Filter tasks assigned to the authenticated user.
* `POST /api/tasks/:id/start`: Transition task to `In Progress`.
* `POST /api/tasks/:id/complete`: Complete task (enforces mandatory evidence validation).
* `POST /api/tasks/auto-schedule`: Trigger automatic recurring schedule and overdue evaluator.

### Audits & Checklists
* `GET  /api/audits`: List audits with compliance scores and findings count.
* `POST /api/audits`: Schedule an internal or buyer audit.
* `GET  /api/audits/:id`: Fetch audit details, scope, and checklist items.
* `PUT  /api/audits/checklist/:id`: Update item finding, severity, and auto-raise NC.

### Non-Conformities (NC) & 5×5 Risk
* `GET  /api/ncs`: List NCs with severity, aging bracket, and status filters.
* `POST /api/ncs`: Raise an NC with likelihood and impact scores.
* `GET  /api/ncs/:id`: Detailed NC dossier with CAP history and audit trail.
* `POST /api/ncs/:id/close`: Close NC (enforces verification pass check).
* `GET  /api/ncs/aging-report`: Distribution of NCs across 0-7d, 8-15d, 16-30d, 31-60d, 60d+.

### Corrective Action Plans (CAP)
* `POST /api/caps`: Draft a 4-part CAP (Immediate, Root Cause, Corrective, Preventive).
* `POST /api/caps/:id/submit`: Submit CAP for compliance review.
* `POST /api/caps/:id/review`: Approve or reject CAP with reviewer remarks.
* `POST /api/caps/:id/submit-evidence`: Link uploaded documentation for verification.
* `POST /api/caps/:id/verify`: Auditor verification (Pass / Fail) with notes.

### Settings & Dynamic Scoring
* `GET  /api/settings/score-config`: Retrieve current scoring weights and pass threshold.
* `PUT  /api/settings/score-config`: Update penalty weights for Critical, Major, and Minor NCs.
* `GET  /api/settings/escalation-config`: Retrieve escalation thresholds (2d reminder, 3d, 7d, 14d).
* `PUT  /api/settings/escalation-config`: Update escalation parameters.
* `GET  /api/settings/audit-logs`: Query immutable system audit logs with before/after state diffs.
